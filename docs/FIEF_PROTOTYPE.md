# Fief Gameplay Prototype v0.2

기준: [영지 시스템 설계서](spec/FIEF_SYSTEM_DESIGN_v0.2.md), [v0.2 실행 프롬프트](spec/FIEF_GAMEPLAY_EXECUTION_v0.2.md). v0.1의 영지·지도·주기 모델을 확장했습니다.

## 접속과 플레이

**http://127.0.0.1:5190/fief**에서 로그인 없이 귀족 테스트 영주의 영지 1개를 관리합니다. 기존 로그인·아틀라스 상단·게임 월드 메뉴의 영지 관리 링크를 유지합니다. 공용 /atlas의 땅에 플레이어 영지를 추가하지 않습니다. /game의 이동·채광·Command/Event 계약도 유지합니다.

시작 시설은 성 L1, 도시 L1, 장원 L1, 영구 던전 고대 지하궁전 1개입니다.

1. 던전 주변 위험과 상단 금고·민심·치안·번영을 확인합니다.
2. 외곽 몬스터가 늘면 **성**을 눌러 병사를 모집하고 순찰을 보냅니다.
3. 내부 에테르가 높으면 **던전**에서 직접 공략하거나 가상 모험가 파티에 토벌 의뢰를 등록합니다.
4. 관리하지 않아 폭주하면 몬스터 웨이브가 도시로 이동합니다. 도착 시 민심·치안·번영이 감소합니다.
5. **도시**에서 피해와 사건을, **장원**에서 금고·경고·시설 요약·최근 기록을 확인합니다.

모든 행동은 시뮬레이션입니다. 실제 전투·다른 유저 매칭·경제·서버 저장은 없습니다. 현재 도시에 적용된 피해는 초기화 전까지 유지되며 복구 정책·방어 전투는 후속입니다.

## 지도·HUD·시설 상황 패널

짙은 녹색·차분한 금색을 유지합니다. 데스크톱은 지도 약 70~75%, 선택 시설 상황 패널 약 25~30%입니다. 긴 규칙과 모든 시설 정보를 기본 화면에 펼치지 않습니다. 상황 패널 내용이 길면 패널 안에서 스크롤합니다.

모바일 412px은 HUD → 지도 → 선택 시설 하단 패널입니다. 페이지 자체의 스크롤로 행동에 접근합니다. 시설은 실제 button으로 터치·키보드 선택합니다. progressbar·status·alert와 키보드 포커스를 제공합니다. 애니메이션 축소 설정에서는 위험 링의 맥동을 멈추며 텍스트·수치는 계속 제공합니다.

에테르 위험 링과 보라·주황 계열 외부 몬스터 압력을 구분합니다. 압력 단계에 따라 몬스터 마커 0/2/4/5개, 순찰 시 성→던전 경로와 경비병, 가상 파티 공략 시 플레이어 프레임, 폭주 시 던전→도시의 3~5개 몬스터를 표시합니다. 위치는 모델의 진행 시간으로 계산하며 별도 애니메이션 라이브러리·루프를 만들지 않습니다.

한국어·영어·일본어·중국어·베트남어를 지원합니다. 기존 AtlasSprite·AssetManager와 실제 등록된 settlement.city/castle/manor, world.dungeon/npc.guard/player/monster 프레임을 재사용합니다.

## 던전 등급·주기 보존

| 도시 | 다음 주기 등급 |
| ---- | -------------- |
| L1   | F / E / D      |
| L2   | D / C          |
| L3   | D / C / B      |
| L4   | C / B / A      |
| L5   | B / A / S      |

시퀀스 인덱스는 (주기 번호 − 1) % 허용 등급 수입니다. 도시 변경은 다음 주기부터 반영하고, 성 레벨은 등급 선택에 관여하지 않습니다. 초기 등급 F와 던전 ID·이름·위치는 유지합니다. 등급에 따라 몬스터·보스·자원 샘플이 바뀝니다.

21일 운영 설계값과 120초 개발 주기를 유지합니다. 기본은 120초입니다. 시간 모드 변경은 주기 진행 비율을 보존합니다. 다음 등급 예고는 테스트 주기의 마지막 30초, 설계 시간 비교의 마지막 1일에 표시합니다. 도시 변경 시 예고를 새 범위로 갱신합니다.

## PROTOTYPE_CONFIG: 임시값

**운영 밸런스 확정값이 아닙니다.** src/modules/fief/config.ts 한 곳에서 관리합니다.

| 항목                               | 현재 테스트값                                                |
| ---------------------------------- | ------------------------------------------------------------ |
| 초기 금고 / 민심 / 치안 / 번영     | 10,000 / 70 / 70 / 60                                        |
| 초기 에테르 / 몬스터 압력 / 주둔군 | 12 / 18 / 40                                                 |
| 에테르 증가                        | 초당 0.6 + 등급 인덱스 × 0.12                                |
| 압력 증가                          | 초당 0.25 + 등급 인덱스 × 0.08                               |
| 에테르 구간                        | 35 불안정, 65 위험, 85 폭주 임박, 100 폭주                   |
| 압력 구간                          | 35 증가, 65 위험, 85 매우 위험                               |
| L1 병력 수용 / 성 레벨당 추가 수용 | 80 / 40                                                      |
| 병사 모집                          | 500 G, +20명; 잔액·수용 한도 검사                            |
| 성 순찰                            | 250 G, 필요 병력 10명, 6초, 압력 −40                         |
| 직접 공략                          | 준비 1초 + 공략 5초, 에테르 −35                              |
| 토벌 의뢰                          | 등록 시 1,000 G, 3초 후 수락, 1초 준비, 5초 공략, 에테르 −50 |
| 웨이브                             | 8초 이동, 민심 −5 / 치안 −8 / 번영 −3                        |
| 개발 조작                          | 시간 +30초, 에테르 +20, 압력 +20, 금고 +5,000                |

에테르·압력은 0~100, 피해 상태도 0~100입니다. 설계 시간 비교 모드는 두 자연 증가율을 120초/21일 비율로 환산합니다. 순찰·공략·의뢰·웨이브 행동은 양쪽 모드 모두 위의 짧은 실제 초 단위로 진행합니다.

성 관리 여력은 v0.1의 임시 등급-레벨 비교이며 병력·순찰·실제 전투 전체를 의미하지 않습니다. 모집은 비용과 병력만 변경합니다.

## 행동과 안전 조건

- 순찰: ON_PATROL → SUCCEEDED. 시작에 비용을 한 번 차감하고 완료에 외부 압력만 줄입니다. 에테르는 순찰로 감소하지 않으며 같은 시간에 자연 증가할 수 있습니다.
- 직접 공략: PREPARING → IN_PROGRESS → SUCCEEDED. 완료 전 에테르를 낮추지 않으며 중복 시작을 막습니다.
- 의뢰: NONE → POSTED → ACCEPTED → IN_PROGRESS → SUCCEEDED. 은빛등불 가상 파티가 결정론적으로 참여합니다. 등록에 비용을 한 번 차감하고 완료에 에테르를 낮춥니다. 활성 의뢰의 재등록·완료 중복을 막습니다.
- 금고가 부족하면 행동을 시작하지 않고 비용도 차감하지 않습니다. 정상 화면에는 돈 생성 버튼이 없습니다.
- 에테르 100이 폭주 조건입니다. **압력 100은 폭주를 발생시키지 않습니다.**
- 각 폭주에 고유 ID와 웨이브를 부여하고 도시 도착 피해를 한 번만 적용합니다. 압력은 3/4/5개 아이콘 수에만 반영하며 피해량은 바꾸지 않습니다.
- 에테르를 낮춘 뒤 다시 100에 도달하면 새 폭주가 가능합니다. 먼저 발생한 웨이브는 계속 이동하여 각자 한 번 피해를 적용합니다. 에테르를 낮추거나 주기를 변경해 이미 출발한 웨이브를 지우지 않습니다.

## DEV 패널

작은 DEV 버튼은 기본 닫힘입니다. 정상 화면에는 도시·성 레벨 선택, 시간 모드·정지·+30초·다음 주기, 수치 증가, 폭주 트리거·초기화·긴 테스트 설명을 노출하지 않습니다.

DEV에 이들 제어와 v0.1 즉시 공략을 유지합니다. 안정적인 fief-dev-* data-testid를 제공합니다. Escape나 닫기 버튼으로 닫고 DEV 버튼으로 포커스를 돌려줍니다. 초기화는 전체 상태·진행 행동·웨이브·기록을 초기화하고 자동 시간을 재개합니다.

## 시간·수명·구현 구조

advanceFief 하나에서 에테르·압력·주기·순찰·직접 공략·의뢰·웨이브를 함께 진행합니다. 사건 경계에서 시간을 분할하여 큰 시간 조작과 작은 tick이 같은 결과를 냅니다. 에테르 최대 도달을 먼저 처리하고 행동 완료·도시 도착·주기 갱신을 이어 처리합니다.

React의 250ms interval은 하나뿐입니다. pause는 모든 모델 시간을 멈추고 수동 +30초는 전체 모델을 진행합니다. 숨겨진 탭은 시간 기준을 갱신하여 오프라인 시간을 합산하지 않습니다. 활성 tick 지연은 최대 5초를 반영합니다. 화면 이탈 시 interval·visibilitychange·DEV Escape 리스너를 해제합니다.

새로고침·재진입은 초기 상태로 돌아갑니다. DB·브라우저 영속화·운영 서버 스케줄러를 추가하지 않았습니다. 관리 기록과 완료 웨이브 이력은 각각 최대 12개이며 진행 중 웨이브는 보존합니다.

주요 파일: model.ts(순수 전이), config.ts(임시 수치), FiefPage.tsx(수명·HUD·선택), ContextPanel.tsx(시설 행동), DeveloperPanel.tsx(개발 조작), FiefMap.tsx(기존 지도+모델 기반 이동), copy.ts(5개 언어), fief.css(반응형).

## 후속 범위

왕·작위 경쟁·다중 영지·서버 저장·21일 운영 스케줄러·실제 경제/세금/인구·PvP/공성/전투·타인 매칭·월드 던전 생성/소멸·SS 이상 다중 파티 레이드는 포함하지 않습니다.
