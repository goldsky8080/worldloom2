# Fief Management v0.3 검증 · 2026-09-18

기준 commit: `f69aecc75d4c8d29478118441643286c9ffc3208` (`main`). Windows / Node 22.9.0 / 기존 React·Vite·TypeScript·Pixi 프로젝트에서 검증했습니다. 새로운 패키지나 이미지 의존성을 추가하지 않았습니다.

## 정적·단위 검사

- 전체 단위 검사 **167개 통과**: 기존 132개를 유지·변경하고 관리 모델 33개, 관리 UI 2개를 추가했습니다.
- ESLint, Prettier, TypeScript 및 운영 빌드 통과.
- 기존 Pixi 청크의 500 kB 경고는 유지되며 운영 빌드는 성공합니다.
- 기존 등급·도시 범위·주기·던전 ID·성 독립·예고·직접 공략·의뢰·웨이브 검사를 유지했습니다. Pressure/순찰/즉시 모집 검사는 Monster Saturation/비상 토벌/지연 모집의 실제 동작으로 갱신했습니다.

새 관리 모델 검사에서는 다음을 확인합니다.

1. 에테르 폭주만 Dungeon Break를 일으키고 포화도 100만으로는 폭주하지 않습니다. 폭주 ID당 포화도 급증과 웨이브 발생은 한 번이며, 이미 출발한 웨이브는 후속 행동이나 재폭주로 사라지지 않습니다.
2. 정상·부상·전사, 상시·비상 배치, 가용 방어 병력의 관계를 유지합니다. 전사자는 복귀하지 않고 생존 정원을 차지하지 않으며, 부상자와 진행 중 모집은 정원 계산에 포함합니다. 병력이나 예약 모집을 지우는 성 레벨 하향은 거절합니다.
3. 상시 토벌은 자동으로 포화도를 억제하고 낮은 포화도에서 효율이 줄어듭니다. 누적 노출에 따른 부상·전사는 결정적으로 적용되며 배치 병력도 감소합니다. 배치 해제만으로 손실 노출을 초기화하지 않습니다.
4. 선택한 수의 모병 비용은 시작 시 한 번 차감되고 완료 시에만 정상 병력으로 편입됩니다. 중복 모집, 선택 최대치·정원 초과·금고 부족을 막으며 진행 중 모집의 견적은 유지합니다.
5. 비상 토벌은 가용 정상 병력을 예약하고 비용·시간·부상·전사를 적용합니다. 완료 시 포화도만 감소시키며 에테르를 직접 낮추거나 출발한 웨이브를 없애지 않습니다.
6. 높은 포화도는 치안·번영·민심 순으로 더 강하게 지속 피해를 줍니다. 조건을 만족한 뒤 치안부터 지연 회복하고 번영·민심은 추가 조건과 지연을 요구합니다. 80 이상은 느리게 회복하지만 100까지 도달할 수 있습니다. 낮은 상태 수치만으로 별도 악순환 피해를 만들지 않습니다.
7. 세율은 수입·지속 부담·회복 계수에 영향을 주며 즉시 상태 수치를 올리거나 금고를 지급하지 않습니다. 장원 레벨별 정책 슬롯·해금·대기시간·유지비·지원 효과와 자금 부족 시 정책 자동 중단을 확인합니다. 병력 급료 부족만으로 병력을 임의 삭제하거나 게임을 종료하지 않습니다.
8. 30초 세금·급료·정책 정산, 회복 완료·손실·모병·비상 토벌·웨이브·주기 경계가 큰 시간 증가와 작은 tick에서 같은 결과를 냅니다. 비정수 시간, 포화도 지수 억제 구간과 위험 구간의 경계도 포함합니다.

UI 검사에서는 StrictMode에서도 interval 하나만 실행되는지, pause·unmount의 interval/visibility 리스너 정리, 숨김 탭의 오프라인 시간 합산 방지, DEV 기본 닫힘·Escape 포커스 복귀, 중복 직접 공략 차단을 유지했습니다. 선택 수량 모병의 지연 완료·상시 배치·가용 병력·잘못된 수량 차단, 세율 변경 대기와 정책 슬롯·비즉시 효과를 추가했습니다.

경계 보정은 작은 부동소수 오차를 임계값에 정렬합니다. 특히 번영도가 정확히 30인 상태에서 높은 세율 때문에 감소하기 시작하면 민심 회복 조건을 즉시 닫습니다. 사건 ID·순서·정수 병력·금고는 정확히 비교하며, 실수 상태/타이머/로그 에테르 값은 허용 오차 내에서 비교합니다.

## 실제 브라우저

**68개 고유 시나리오 통과**: 관리 v0.3 16개 + 기존 영지 12개 + 기존 게임플레이 14개 + 게임·아틀라스 회귀 26개. 데스크톱 1440×900과 Pixel 7 412×839를 각각 검증했습니다.

관리 시나리오 8개 × 2개 화면:

1. 상시 병력 20명 배치 → 가용 20명 → 자동 포화도 감소·지도 이동 마커, 초과 배치 차단.
2. 상시 토벌의 부상·전사·배치 감소 → 배치 해제 → 부상 복귀, 전사자는 그대로 손실.
3. 20명 모병 비용 500 G 한 번 차감 → 진행률·모집 잠금 → 10초 후 정상 병력 60명, 중복 완료 없음.
4. 폭주 포화도 18→53·웨이브 4개 → 비상 20명 비용 200 G·이동 → 완료 부상 3·전사 1·포화도 감소, 에테르 100과 출발 웨이브 유지.
5. 포화도 100에서 폭주 없이 지속 피해, 치안 > 번영 > 민심 피해 속도.
6. 안전 조건에서 치안 먼저 회복 → 지연된 번영 → 더 늦은 민심 회복과 조건 안내.
7. 낮은 세율·변경 대기·반복 수입/급료/유지비, 슬롯·장원 레벨·정책 해금, 금고 부족 시 정책 자동 중단.
8. 5개 언어에서 새 군사·행정 UI 번역, 시설 터치, DEV 숨김, 가로 넘침·브라우저 오류 없음.

기존 영지·게임플레이의 직접 공략·의뢰 준비/진행/완료, 한 번 차감과 중복 차단, 웨이브 피해와 재폭주·겹친 웨이브, 주기·등급·21일 시간 모드·DEV·다국어·시간 숨김/정지·시설 선택·라우트 왕복을 유지했습니다. 유료 행동의 금고 부족 검사는 반복 수입이 도입된 규칙에 맞게 DEV 금고 비우기로 조건을 고정합니다.

게임·아틀라스 회귀 26개는 로그인·가입·패널·우편·채팅·다국어, 거리 이동·채광·인벤토리 보상, Gap/Replay·세션 만료·패널 복구, 아틀라스 LOD·모바일 핀치·소유/통치·장면·아이템·오류 재시도를 확인합니다. 생산용 core/world/mining 및 이 회귀 시나리오는 변경하지 않았습니다.

행동 시간 검증은 Playwright 가상 시계를 사용하며, Pixi와 라우트 왕복 시나리오는 실제 시계를 사용합니다. 새 관리 시나리오는 Chromium 기본 그래픽 합성과 WebGL 소프트웨어 fallback을 사용합니다. 이전 게임·아틀라스 시나리오의 그래픽 설정은 유지합니다. 검사 출력은 별도 폴더로 분리합니다. 회귀 검사 종료 시 Vite가 .cache 아래의 임시 trace 파일 삭제를 감시하다 Windows EPERM을 출력했습니다. 26개 assertion은 모두 통과했고 검사 exit code는 0이었습니다. 종료 후 실제 5190/fief HTTP 200과 기존 서버 프로세스 유지도 확인했습니다. 이후 재현 명령은 기존 Vite 감시 제외 경로인 test-results/regression-v03를 사용합니다.

## 재현·임시 수치·후속 범위

```powershell
npm test
npm run lint
npm run format:check
npm run build
npx playwright test e2e/fief.spec.ts e2e/fief-gameplay.spec.ts e2e/fief-management.spec.ts
npx playwright test e2e/framework.spec.ts e2e/atlas.spec.ts --output test-results/regression-v03
```

별도 Chromium은 PLAYWRIGHT_CHROMIUM_EXECUTABLE로 지정합니다. 기존 서버를 검증할 때는 PLAYWRIGHT_EXTERNAL_SERVER=1과 PLAYWRIGHT_BASE_URL을 지정합니다.

비용·시간·확률 대신 적용한 결정적 손실 규칙·증가/피해/회복률은 모두 **PROTOTYPE_CONFIG의 임시 검증값**입니다. 금고 10,000 G·정상 병력 40명, 모병 25 G/명·2+0.4n초, 비상 10 G/명·6초, 부상 회복 30초, 세금/급료 정산 30초, 세율/정책 대기 20초 등은 운영 확정값이 아닙니다. 자연 주기/증가만 120초 테스트와 21일 설계 모드로 변환하며, 관리 행동·회복·정산은 두 모드 모두 짧은 실제 초 단위로 시연합니다. 자세한 수식과 조건은 [FIEF_PROTOTYPE.md](FIEF_PROTOTYPE.md)에 기록했습니다.

구현은 프런트엔드 메모리 상태이며 새로고침/재진입 시 초기화합니다. 백엔드·DB·지속 저장·WebSocket·오프라인 정산·실제 전투·정식 영지 업그레이드 경제·개인 지갑·타 유저 의뢰 매칭·작위/의회·월드 던전·특수 병과·치료소·반란 및 실기기 GPU 성능은 후속 범위입니다.
